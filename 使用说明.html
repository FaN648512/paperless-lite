paperless-lite 使用说明

票据合同 OCR 文档库 · paperless-ngx 保真复刻版 · 适用于零基础用户

一、这是什么？

这是一个本地文档管理器，专门管理扫描件、照片版的票据和合同。你把文件丢进去，它自动完成三件事：

  • 认字（OCR）—— 图片和扫描版 PDF 里的文字会被自动识别出来
  • 贴标签—— 按你定好的规则自动分类：发票、合同、收据、检测报告……
  • 能搜索—— 之后输入任何一个词（比如「12800」「职业病」）都能秒搜到那份文件

它复刻了开源项目 paperless-ngx（4.5 万 star）的核心玩法，全部在你的电脑本地运行，不需要联网、不需要任何账号或 API Key，文件不会离开你的电脑。

二、怎么启动和关闭

操作方法
启动打开文件夹 paperless-lite\，双击 启动服务.pyw。会弹出一个控制台窗口（守护进程：服务万一崩溃会 3 秒内自动重启，别关错），然后浏览器自动打开界面。
关闭直接关掉那个守护进程控制台窗口即可。界面本身关掉不影响数据。
地址浏览器输入 127.0.0.1:8765 随时访问（服务开着的时候）。
⚠️ 启动前建议先关掉 Firefox 和 QQ——这台机器内存只有 3.9 GB，OCR 识别时需要较多内存。数据都存在硬盘上，关机、重启都不会丢。

三、界面导览

区域有什么用
顶部搜索框输入任意词回车即搜，命中文字会黄色高亮。支持 2 个字的长度的词、数字、日期、身份证号。
左侧标签栏点某个标签 = 只看该类文件；标签后面的数字是文件数量。点「全部」恢复显示所有文件。
中间卡片网格每张卡片是一份文件，显示缩略图、标题、往来单位和标签。
右侧详情面板点开卡片后显示：大图预览、OCR 识别出的全文、往来单位、文件类型、标签（可手动增删）。

四、核心玩法：四步上手

  1. 上传——点右上角「上传」按钮，一次可以选多个文件（png / jpg 图片，或 PDF）。
  2. 等它处理——卡片上会显示处理进度。识别完的卡片会自动带上标题、往来单位和标签。每页大约需要 10 秒，是这台 2 核 CPU 的正常速度，批量上传时它会排队一份一份处理。
  3. 搜索——在顶部搜任何你记得的词。比如搜「12800」能找到那份金额里含这个数的发票。
  4. 管标签——在详情面板里可以手动给文件加减标签；想自动化就去「规则」页面配置。

五、自动标签规则怎么配（最好玩的部分）

规则 = 「文件里出现某些字 → 自动打上某标签」。支持四种匹配方式：

匹配方式含义例子
任意词包含其中任何一个词就命中规则「发票」匹配 增值税,发票,专用 → 文中出现任一词即打标
全部词必须同时包含所有词才命中规则「双方合同」匹配 甲方,乙方 → 两词都有才算合同
正则用正则表达式精确匹配模式NO\.\d{8,} 匹配所有「NO.12345678」格式的单据编号
全文包含这一整句话才命中匹配完整句子「职业健康检查结果」

规则创建后点「应用规则」，会对所有已入库文件重新匹配一遍；停用某条规则再应用，它打的标签会自动移除，不会留垃圾数据。

六、常见问题

现象原因与解决办法
OCR 识别慢（每页 ~10 秒）正常现象。CPU 只有 2 核，已经是这台机器的物理极限，批量上传会自动排队，放着让它跑就行。
搜某个词搜不到，但文件里明明有大概率是 OCR 形近字：比如「叁」被认成「参」。换不含形近字的片段搜索即可。
上传后一直「处理中」前面还有文件在排队（串行处理）。多等几分钟；若超过 10 分钟，刷新页面看状态。
界面打不开服务没启动或被关了 → 重新双击 启动服务.pyw。
提示端口被占用（8765）已经有一个服务在跑了，直接浏览器打开 127.0.0.1:8765 即可。
想备份数据双击 备份数据.pyw 一键完成（自动存到 E:\paperless-lite-backup\时间戳\，保留最近 5 份）。手动备份则复制 E:\paperless-lite-data 整个文件夹。
想给同事共享访问看下面「七、让同事在公司里访问」一节

七、让同事在公司里访问

做完下面三步，同事在公司网络里用浏览器就能搜 / 看 / 下载你的文档。整套 5 分钟搞定，全程无需联网、无需外部账号。

第 1 步 · 打开防火墙端口（一次就够）

双击项目里的 局域网共享.py，会弹出黑色控制台窗口。选 1「开放局域网访问」，弹出的「用户账户控制」点「是」。这一步给你的电脑加一条防火墙放行规则，只对「公司/专用网络」开放，对咖啡厅之类「公用网络」不开放。

完成后窗口会显示同事的访问地址，例如 http://192.168.1.100:8765。把这个地址发给同事就行。

第 2 步 · 首次打开设置账号密码

同事（或你自己）在浏览器打开那个地址，会先看到一个「设置访问密码」页面 —— 这是为了避免库一开始就裸奔：

  • 填一个登录账号（比如「admin」或者你的名字）
  • 填一个至少 6 位的密码
  • 再输一次密码确认 → 点「设置并进入」

密码只存在你自己电脑的 E:\paperless-lite-data\auth.json 里（哈希存的，不是明文），不会外传、不会上传到任何地方。之后同事每次打开都要先输这个账号密码才能看到文档。

第 3 步 · 同事打开地址，登录，开始搜

同事用自己的电脑浏览器输 http://你的IP:8765，输账号密码登录后即可搜索 / 查看 / 下载全部文档（完全管理权限：能上传、删、改标签 —— 你做老板嘛）。

顶栏右上角有个「退出」按钮，共用一台电脑时换人用得到。

用完想关掉同事访问怎么办？
双击 局域网共享.py → 选 2「关闭局域网访问」，防火墙规则就被删了，再没人能连进来。你自己照常用 127.0.0.1:8765 访问，不受影响。
同事访问不了？按这个顺序查原因与解决办法
同事浏览器打不开地址① 你自己先开 127.0.0.1:8765，确认服务在跑；② 让同事 ping 你的 IP，不通说明不同网段，得找网管；③ 用你电脑的浏览器开 http://你的IP:8765，你自己都打不开就是防火墙没生效，重新跑一遍「开放局域网访问」。
同事打开页面看到「错误次数太多」同事输错密码超过 5 次，TA 的 IP 被锁 5 分钟（5 分钟自动解开；急用就让你重启 启动服务.pyw，立即解锁）。
你忘记密码了关掉服务 → 删掉 E:\paperless-lite-data\auth.json → 重新启动服务 → 打开页面会要求重新设置账号密码。文档、标签、规则都不受影响。
公司有人反馈搜不到你机器可能是公司网络做了 AP 隔离（同一 WiFi 下不允许互相访问），需要公司网管把你们的 IP 加入「允许互通」名单，或把库部署到公司服务器。
三个真实存在的风险，老实跟你说清楚：
  • 同事用的网络是明文 HTTP，懂技术的人能抓包看到合同内容。公司内网一般可接受，但跟访客 WiFi 混用就别开。
  • 这台机器只有 3.9 GB 内存、2 核 CPU，同事上传文件会触发 OCR 排队。偶尔一两个没事，同时传会卡死。
  • 绝对不要做内网穿透（花生壳 / frp / ngrok 等），把库暴露到公网会引来公网爬虫扫描 —— 风险远大于便利。

八、文件位置速查

路径内容
paperless-lite\app.py后端主程序（一般不用动）
paperless-lite\core\数据库 / 规则引擎 / OCR 处理管线
paperless-lite\static\网页界面（HTML / CSS / JS）
E:\paperless-lite-data\你的全部数据（数据库 + 原始文件 + 缩略图），备份就备份它
E:\paperless-lite-backup\一键备份的存放地，按时间戳分文件夹，自动保留最近 5 份
paperless-lite\备份数据.pyw数据一键备份（双击即可，服务运行中也能安全备份）
paperless-lite\tools\verify_all.py自动验收脚本，27 项检查，怀疑出问题时可跑一次
paperless-lite\启动服务.pyw一键启动器（双击它）
paperless-lite\局域网共享.py让同事访问（双击它：1 开放 / 2 关闭 / 3 查看状态）
